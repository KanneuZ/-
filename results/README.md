# Результаты тестирования SLAM-алгоритмов (NGD-SLAM и DPVO)

В этой папке собраны результаты тестирования двух алгоритмов SLAM:
1. **NGD-SLAM** (RGB-D) — использует нейросеть YOLO для фильтрации динамики и метрическую глубину.
2. **DPVO** (Монокулярный) — использует только RGB-кадры, глубина не требуется.

Для каждой сцены создана отдельная папка, в которой лежат:
- Исходные траектории (`gt.txt`, `ngd.txt`, `dpvo.txt`).
- Отдельные графики для каждой траектории (`plot_gt.png`, `plot_ngd.png`, `plot_dpvo.png`).
- Общий график сравнения (`plot_all.png`).
- Файл `README.md` с метриками (ATE RMSE) и описанием.

## 🔍 Краткий анализ

1. **На статичных сценах TUM (fr1):** NGD-SLAM показал превосходную точность (0.0108 м), так как использовал настоящую метрическую глубину с датчика Kinect. DPVO без глубины ошибся на 13 см.
2. **На динамичных сценах TUM (fr3_walking):** NGD-SLAM снова победил (0.0156 м), так как YOLO успешно вырезал движущихся людей из трекинга. DPVO "поплыл" (0.0909 м), воспринимая людей как часть сцены.
3. **На сцене fr2:** NGD-SLAM показал плохой результат (0.365 м), вероятно, из-за ложного срабатывания YOLO на статичных объектах. DPVO оказался точнее (0.0418 м).
4. **На синтетике Replica:** DPVO показал себя лучше (0.56–0.72 м), так как на синтетических текстурах монокулярная одометрия работает стабильно, а NGD-SLAM немного "плывет" из-за особенностей глубины.
5. **На собственной съёмке (apartment):** NGD-SLAM упал из-за отсутствия метрической глубины (MiDaS не подходит). DPVO построил траекторию с ошибкой 2.9 м из-за наличия зеркал и разворота камеры.

## 📌 Примечания
- **ATE (Absolute Trajectory Error)** — абсолютная ошибка траектории. Рассчитана с помощью библиотеки `evo` (метод Umeyama с выравниванием масштаба для DPVO).
- **Пройдено пути** — отношение длины траектории алгоритма к длине GT. Если >100%, алгоритм "перелетел" (намотал лишнее).
- Для Replica метрики рассчитаны по среднему отклонению на синхронизированных кадрах (так как время в файлах GT и алгоритмов не совпадает).
